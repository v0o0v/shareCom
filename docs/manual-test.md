# 실기 확인 목록

자동 시험으로 확인할 수 없는 부분(실제 마우스·키보드, 두 PC 사이 와이파이)을 사람이 직접 확인하는 목록이다. 단계마다 해당 절을 채운다.

## 준비

1. 이 PC에서 배포용 exe 를 만든다.

   ```bash
   dotnet publish src/ShareCom.App -c Release -o publish
   ```

2. `publish\ShareCom.exe` 를 두 PC에 복사한다(USB, 공유 폴더 등). 폴더 위치는 어디든 된다.
3. 두 PC에서 각각 `ShareCom.exe` 를 실행한다. UAC 창에서 [예]를 누른다.
   - Windows SmartScreen 이 "알 수 없는 게시자"라며 막으면 [추가 정보] → [실행]을 누른다(서명하지 않은 exe 라서 뜬다).
4. 작업 표시줄 오른쪽 트레이에 모니터 두 대 모양 아이콘이 생긴다. 회색은 연결 없음, 초록은 연결됨, 파랑은 다른 PC를 조작 중이다.

문제가 생기면 트레이 메뉴 [기록 폴더 열기]의 `log.txt` 를 보거나 그대로 전달한다.

## 2단계: 클립보드

1단계 짝 맺기가 끝난 두 PC에서 확인한다. 트레이 메뉴 [클립보드 공유]가 양쪽 모두 켜져 있어야 한다(기본 켬).

| # | 할 일 | 기대 결과 | 결과 |
|---|---|---|---|
| 2-1 | PC A 메모장에서 한글·영문·이모지 글을 복사 → PC B 메모장에 붙여넣기 | 같은 글이 붙는다 | |
| 2-2 | PC A 웹 페이지(굵은 글씨·링크 포함)를 복사 → PC B 워드/한글/Outlook 에 붙여넣기 | 서식이 살아 있다 | |
| 2-3 | PC A 에서 Win+Shift+S 로 화면 일부 캡처 → PC B 그림판에 붙여넣기 | 같은 그림이 붙는다 | |
| 2-4 | 투명 배경 PNG 를 이미지 편집기에서 복사 → PC B 에 붙여넣기 | 투명도를 아는 프로그램에서는 투명하게 붙는다 | |
| 2-5 | 아주 큰 이미지(예: 8000×8000) 복사 직후 PC B 로 마우스를 옮긴다 | 마우스는 끊기지 않고, 잠시 뒤 PC B 에 붙여넣을 수 있다 | |
| 2-6 | PC B 에서 복사 → PC A 에 붙여넣기 | 반대 방향도 된다 | |
| 2-7 | 비밀번호 관리자(예: 1Password, Bitwarden, KeePass)에서 비밀번호 복사 | PC B 에 넘어가지 않는다(기록에 "공유 제외 표시" 가 남는다) | |
| 2-8 | 한쪽에서 [클립보드 공유]를 끄고 복사 | 넘어가지 않는다. 다시 켜면 넘어간다 | |
| 2-9 | 탐색기에서 파일을 복사 | 파일 목록이 넘어간다(붙여넣기는 3단계 표에서 확인) | |

클립보드 읽기·쓰기 자체는 진단 명령으로도 확인할 수 있다. 결과 파일 끝에 `RESULT PASS` 가 나와야 한다. 지금 클립보드 내용은 시험이 끝난 뒤 되돌린다.

```bash
ShareCom.exe --selftest-clipboard result.txt
```

## 3단계: 파일 옮기기

1단계 짝 맺기가 끝난 두 PC에서 확인한다. 받은 파일은 `다운로드\shareCom` 에 저장된다(트레이 메뉴 [받은 파일 폴더 열기]).

### 탐색기 복사·붙여넣기

| # | 할 일 | 기대 결과 | 결과 |
|---|---|---|---|
| 3-1 | PC A 탐색기에서 파일 하나를 Ctrl+C → PC B 탐색기 아무 폴더에서 Ctrl+V | 탐색기 복사 창이 뜨고 같은 파일이 생긴다 | |
| 3-2 | 하위 폴더·빈 폴더·한글 이름이 있는 폴더를 통째로 복사 → 붙여넣기 | 폴더 구조가 그대로 생긴다 | |
| 3-3 | 수 GB 파일을 복사 → 붙여넣기 중 마우스를 PC A 로 옮겼다가 다시 PC B 로 | 마우스·키보드는 끊기지 않고, 복사가 이어진다 | |
| 3-4 | 붙여넣기 중 탐색기 복사 창에서 [취소] | 복사가 멈추고, PC A 쪽에 오류가 남지 않는다 | |
| 3-5 | 붙여넣기 중 PC A 의 ShareCom 을 끈다 | PC B 탐색기에 복사 오류가 뜬다(부분 파일이 남을 수 있다) | |
| 3-6 | 같은 폴더에 두 번 붙여넣기 | 탐색기가 덮어쓸지 묻는다(탐색기 기본 동작) | |
| 3-7 | PC A 에서 파일을 복사한 뒤 PC A 에서 원본을 지운다 → PC B 에 붙여넣기 | 오류가 뜨고 다른 파일은 영향이 없다 | |
| 3-8 | PC B 에서 복사 → PC A 에 붙여넣기 | 반대 방향도 된다 | |

### 트레이 메뉴로 보내기

| # | 할 일 | 기대 결과 | 결과 |
|---|---|---|---|
| 3-9 | PC A 트레이 메뉴 [파일 보내기] → PC B → [파일 고르기…] 에서 여러 파일 선택 | PC B 에 받을지 묻는 창(파일 수·크기·저장 위치)이 뜬다 | |
| 3-10 | PC B 에서 [받기] | 진행 창이 뜨고, 끝나면 `다운로드\shareCom` 에 파일이 있다. PC A 에 "다 보냈습니다" 알림 | |
| 3-11 | 같은 파일을 한 번 더 보내고 받는다 | `이름 (2).확장자` 로 저장된다 | |
| 3-12 | [폴더 고르기…] 로 폴더를 보낸다 | 폴더 구조가 그대로 저장된다 | |
| 3-13 | PC B 에서 [거절] | PC A 에 "거절했습니다" 알림 | |
| 3-14 | 받는 중 진행 창에서 [취소] | 멈추고 임시 파일(`.sharecom-part`)이 남지 않는다 | |
| 3-15 | 받을지 묻는 창을 오래 둔 뒤 [받기] | 시간 제한 없이 받는다 | |

탐색기 붙여넣기 경로는 진단 명령으로도 확인할 수 있다. 원본 폴더 안 항목을 가상 파일로 클립보드에 올리고 정한 초 동안 기다리니, 그동안 탐색기에서 붙여넣어 본다. 끝나면 원래 클립보드 내용을 되돌린다.

```bash
ShareCom.exe --selftest-files 원본폴더 60
```

## 4단계: 화면 배치·모니터 여러 대·최대 4대

PC 3대(A, B, C)가 있으면 모두 확인한다. 2대뿐이면 4-1 ~ 4-4, 4-7 ~ 4-12 를 확인한다. 4단계부터 통신 버전이 2라서 모든 PC의 exe 를 함께 바꿔야 한다.

### 자동 소개

| # | 할 일 | 기대 결과 | 결과 |
|---|---|---|---|
| 4-1 | A·B 가 짝인 상태에서 C 를 A 와만 짝 맺는다 | 몇 초 안에 B 와 C 도 서로 연결된다. B·C 에 "자동 소개로 짝이 되었습니다" 알림 | |
| 4-2 | 세 PC 트레이 메뉴를 연다 | 모두 나머지 두 PC 가 "연결됨"으로 보인다 | |
| 4-3 | A 에서 C 를 [짝 풀기…] | 경고 창에 "다른 PC에서도 풀린다"가 보인다. 풀면 B 에서도 C 가 사라지고 C 에서도 A·B 가 사라진다 | |
| 4-4 | C 를 다시 B 와 짝 맺는다 | A 와도 다시 자동으로 짝이 된다 | |

### 배치 편집기

| # | 할 일 | 기대 결과 | 결과 |
|---|---|---|---|
| 4-5 | A 트레이 메뉴 [화면 배치…] | 창에 PC 상자가 보인다. 내 PC 파랑, 연결됨 초록, 연결 안 됨 회색. 모니터 여러 대인 PC 는 상자 안에 모니터가 따로 그려진다 | |
| 4-6 | B 상자를 A 오른쪽 아래 아무 데나 끌어 놓는다 | 가장 가까운 A 가장자리에 딱 붙는다. 다른 상자와 겹치게는 놓이지 않는다 | |
| 4-7 | B 상자를 A 아래쪽에 붙이고 [적용] | A 화면 아래 끝으로 밀면 B 화면 위 끝으로 넘어가고, B 위 끝으로 밀면 A 로 돌아온다 | |
| 4-8 | 4-7 에서 A·B 가 일부만 맞닿게 놓고, 맞닿지 않은 구간의 아래 끝을 민다 | 가장 가까운 맞닿은 구간 끝으로 넘어간다 | |
| 4-9 | 편집기를 연 채로 B 에서 배치를 바꿔 [적용] | A 편집기가 바로 새 배치로 바뀐다(A 에서 아직 옮기지 않았을 때) | |
| 4-10 | 배치를 바꾼 뒤 세 PC 모두 ShareCom 을 껐다 켠다 | 배치가 그대로 남아 있다 | |
| 4-10a | 배치를 바꾼 뒤 [짝 풀기] → 같은 PC와 다시 짝 맺기 | 바꿔 둔 배치 자리로 돌아온다(기본 자리로 바뀌지 않는다). 사이에 ShareCom 을 껐다 켜도 같다 | |
| 4-11 | 상자 번호대로 Ctrl+Alt+2, Ctrl+Alt+3 | 그 번호 PC 로 바로 간다. 번호는 왼쪽부터(같으면 위부터) 매겨진다 | |

### 모니터 여러 대·원격에서 원격으로

| # | 할 일 | 기대 결과 | 결과 |
|---|---|---|---|
| 4-12 | 모니터가 2대인 PC 에서 내 모니터끼리 이어진 가장자리로 민다 | 다른 PC 로 넘어가지 않고 내 다른 모니터로 간다 | |
| 4-13 | 모니터가 2대인 PC 의 바깥 가장자리(배치에서 다른 PC 와 맞닿은 쪽)로 민다 | 그 PC 로 넘어간다 | |
| 4-14 | A → B → C 가 가로로 놓였을 때, A 에서 B 로 넘어간 뒤 B 오른쪽 끝으로 민다 | A 로 돌아오지 않고 바로 C 를 조작한다. 다시 왼쪽으로 밀면 B, 다시 A | |
| 4-15 | 배율이 다른 PC(예: 100% 와 150%)를 맞닿게 놓고 오간다 | 넘어가는 자리가 배치에 그려진 위치와 맞는다 | |
| 4-16 | B 를 끈 상태에서 A → B 쪽 가장자리로 민다 | 넘어가지 않는다(벽). B 를 켜면 다시 넘어간다 | |
| 4-17 | B 의 디스플레이 설정에서 모니터 배치나 해상도를 바꾼다 | A 편집기에 B 의 새 모니터 모양이 반영되고 넘어가는 자리도 맞는다 | |

편집기 모습은 진단 명령으로 가짜 PC 3대를 넣어 그림 파일로 확인할 수 있다.

```bash
ShareCom.exe --selftest-layout 그림.png
```

| 5-5 | 트레이 [설정…]에서 자동 시작을 끄고 [확인] | 작업 스케줄러에서 작업이 사라진다. 재시작해도 켜지지 않는다 | |
| 5-6 | 자동 시작을 켠 상태에서 exe 를 다른 폴더로 옮겨 한 번 실행 | 작업의 실행 경로가 새 위치로 바뀐다(기록에 "다시 등록합니다") | |

| 5-8 | 바로 이동 수정키를 Ctrl+Shift 로 바꾼다 | Ctrl+Shift+2 로 이동하고 Ctrl+Alt+2 는 앱에 그대로 간다. Ctrl+Alt+Esc 긴급 복귀는 그대로 된다 | |
| 5-9 | 5-7·5-8 뒤 ShareCom 을 껐다 켠다 | 바꾼 단축키가 남아 있다. [단축키 보기]도 바뀐 키로 보인다 | |
| 5-10 | [설정…]에서 클립보드 공유·넘기기 잠금을 바꾼다 | 트레이 메뉴의 체크 표시도 같이 바뀐다 | |
| 5-11 | PC A 에서 PC B 로 짝 맺기를 요청하고, PC B 에서 [취소] → 곧바로 다시 요청 | 30초 동안은 PC B 에 확인 창이 뜨지 않는다(B 기록에 "짝 맺기 요청 무시"). 30초 뒤에는 다시 뜬다 | |
| 5-12 | PC B 에 확인 창이 떠 있는 동안 PC C 가 PC B 에 짝 맺기를 요청 | 창이 하나 더 뜨지 않는다 | |

| 5-15 | 5-14 뒤 PC B 의 실제 마우스를 움직이거나 클릭한다 | B 포인터가 다시 보이고 그대로 쓸 수 있다 | |
| 5-16 | PC A 마우스로 PC B 에 넘어가 B 가장자리까지 천천히 밀어 A 로 돌아온 뒤, PC B 의 마우스를 위아래로 움직인다 | B 포인터가 보이고 B 마우스로 움직인다(A 로 넘어가지 않는다). B 마우스로 가장자리를 계속 밀면 A 로 넘어간다 | |

자동 시작 등록·조회·해제는 진단 명령으로도 확인할 수 있다(관리자 권한, 원래 상태는 되돌림). 결과 파일 첫 줄이 `PASS` 면 된다.

```bash
ShareCom.exe --selftest-autostart 결과.txt
```

설정 창 모습은 그림 파일로 확인할 수 있다.

```bash
ShareCom.exe --selftest-settings 그림.png
```

## 6단계: 자동 업데이트 (v0.6.0)

v0.5.x 에서 v0.6.0 으로는 손으로 한 번 바꾼다. 아래는 v0.6.0 이 깔린 PC에서 그다음 릴리즈(예: v0.6.1)가 나왔을 때 확인한다.

| # | 할 일 | 기대 | 결과 |
|---|---|---|---|
| 6-1 | [설정…]을 연다 | "업데이트" 묶음에 자동 업데이트(켬)와 [지금 확인]이 있다 | |
| 6-2 | 새 릴리즈가 없을 때 [지금 확인] | "최신 버전입니다(확인 시각)." | |
| 6-3 | 새 릴리즈를 올린 뒤 [지금 확인] → [예] | 설정 창이 닫히고 ShareCom 이 잠깐 꺼졌다 켜진다. "업데이트했습니다" 알림을 누르면 릴리즈 페이지가 열린다. [설정…] 버전이 새 버전이다 | |
| 6-4 | 6-3 뒤 exe 폴더를 본다 | `ShareCom.old.exe`·`ShareCom.new.exe` 가 남아 있지 않다 | |
| 6-5 | 6-3 뒤 로그아웃·로그인 | 자동 시작이 그대로 되고 방화벽 경고 없이 다른 PC와 붙는다 | |
| 6-6 | 그대로 두고 켠 지 2분 뒤 + 5분 동안 아무것도 만지지 않는다 | 기록에 "업데이트 준비됨" → "적용"이 남고 스스로 새 버전으로 바뀐다 | |
| 6-7 | 6-6 중 다른 PC를 조작하거나 파일을 옮기는 중 | 바뀌지 않는다(기록에 "적용을 미룹니다: …") | |
| 6-8 | [설정…]에서 자동 업데이트를 끄고 [확인] | 스스로 확인하지 않는다. [지금 확인]은 된다 | |
| 6-9 | 휴대폰 핫스팟을 '데이터 통신 연결'로 설정하고 붙은 채 기다린다 | 스스로 받지 않는다(기록에 "종량제 연결이라 … 미룹니다") | |

교체·되돌리기는 진단 명령으로도 확인할 수 있다. 시험용 폴더에 `ShareCom.exe` 와 다른 내용의 `new.exe` 를 두고 실행한다(트레이 앱은 뜨지 않는다).

```bash
ShareCom.exe --selftest-update new.exe 결과.txt ok
```

`ok` 는 새 exe 가 시작 신호를 보내고 이전 파일을 지운다. `fail` 은 새 exe 가 신호 없이 꺼지므로 되돌리고 이전 exe 를 다시 띄운다. 결과 파일의 줄이 모두 `[OK]` 면 된다.
